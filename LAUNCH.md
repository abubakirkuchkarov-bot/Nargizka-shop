# Запуск Nargizka Shop на Turso — пошаговая инструкция

Ветка `turso-launch`. В `main` ничего не слито, рабочий сайт не тронут.

## Что изменилось

| Было | Стало |
|---|---|
| Данные в `/tmp` на Vercel — пропадают при каждом «холодном старте», у разных копий функции разные данные | Turso (libSQL): товары, остатки, заказы, финансы, подписчики, настройки, пароль, настройки почты/SMS |
| Фото в `/tmp` — пропадали | Фото в таблице `images` в Turso, отдаются с долгим кэшем CDN |
| Без `ADMIN_PASSWORD` пароль `admin`; `SESSION_SECRET` случайный на каждой копии функции | В Production без `ADMIN_PASSWORD` и `SESSION_SECRET` вход в админку отключён. Смена пароля закрывает все старые сессии |
| Защита от перебора пароля — в памяти одной копии функции | Счётчики попыток в базе: 8 попыток / 15 мин с одного IP |
| Два одновременных заказа могли продать один остаток | Запись под транзакцией `BEGIN IMMEDIATE` — проверено 10 одновременными заказами |
| Ответ «сохранено» мог уйти до записи | Ответ отправляется только после `COMMIT` |
| Удаление заказа/товара — безвозвратно | Копия удалённого сохраняется в `deleted_rows`; перед импортом — снимок в `backups` |
| «Сбросить к демо-данным» доступен в рабочем магазине | Отключён в Production |
| `/api/health` показывал файлы сервера | Показывает только «база доступна / данные загружены» |
| Испорченные буквы на витрине («Имѝ и фамилиѝ», «Ндреѝ», «Доѝтавка» — 97 мест) | Исправлено |
| Экспорт CSV можно было использовать для формул-инъекций в Excel | Исправлено |
| Уведомления о заказе нигде не вызывались | Telegram администратору, письмо и SMS покупателю — если настроены в админке |

Новые файлы: `db/libsql-http.js` (клиент Turso без npm-зависимостей), `db/store.js` (схема и транзакции), `db/sqlite-local.js` (локальная разработка), `scripts/migrate-to-turso.js`, `scripts/reset-admin-password.js`, тесты `scripts/test/`.

## Шаг 1. Сохраните свежие данные с рабочего сайта (обязательно)

Сейчас рабочие данные сайта живут в `/tmp` и могут отличаться от `data/db.json` в GitHub.
Откройте https://nargizka-shop.vercel.app/admin/ → **Настройки → Скачать резервную копию** → сохраните файл
`nargizka-backup-ГГГГ-ММ-ДД.json`. Именно его переносим. Этот файл с данными покупателей **не кладите в GitHub**.

## Шаг 2. Переменные окружения в Vercel (Settings → Environment Variables → Production)

Уже есть: `TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN`. Добавить:

- `SESSION_SECRET` — сгенерируйте у себя в терминале и вставьте значение:
  `node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"`
- `ADMIN_PASSWORD` — пароль первого входа, не короче 10 символов. После смены пароля в админке он больше не используется.

Для превью-деплоев (Preview) Turso не нужен: они работают на временной базе с демо-данными.
Если хотите проверять превью на настоящей базе — создайте отдельную бесплатную базу `nargizka-shop-preview`,
**не используйте рабочую**.

## Шаг 3. Проверка переноса (ничего не записывает)

```
git fetch && git checkout turso-launch
vercel env pull .env.production.local --environment=production
node scripts/migrate-to-turso.js --source путь/к/nargizka-backup-ГГГГ-ММ-ДД.json
```

Скрипт сделает копию в `backups/` и покажет: сколько товаров/единиц на складе, какие заказы реальные,
какие уйдут в карантин как тестовые (они не удаляются — лежат в таблице `quarantine`).
Если реальный заказ попал в карантин: `--keep-order NS-123456`. Если тестовый не распознан: `--test-order NS-…`.

## Шаг 4. Перенос (нужно ваше решение)

```
node scripts/migrate-to-turso.js --source путь/к/файлу.json --apply
```

Пишет одной транзакцией и только в пустую базу — повторный запуск ничего не испортит. В конце печатает сверку (✓/✗).
По желанию `--restore-test-stock` вернёт на склад единицы, списанные тестовыми заказами (в `data/db.json` это 4 шт. «Аврора» XS).

## Шаг 5. Публикация

1. Создайте Pull Request `turso-launch → main`, дождитесь Preview-деплоя, откройте его и пройдите: витрина, корзина, заказ, вход в админку.
2. Слейте PR — Vercel выпустит Production.
3. Проверьте `https://nargizka-shop.vercel.app/api/health` → `{"ok":true,"storage":"turso",...}`.
4. Войдите в админку паролем из `ADMIN_PASSWORD` и сразу смените его в Настройках.
5. Оформите один тестовый заказ и отмените его в админке (остаток вернётся).

Откат: в Vercel → Deployments → предыдущий деплой → **Promote to Production**. Данные в Turso при этом не теряются.

## Полезное

- Забыли пароль: `node scripts/reset-admin-password.js` (нужен `.env.production.local`).
- Тесты: `npm test` (эмулятор Turso + 2 копии сервера), `python3 scripts/test/ui_check.py http://localhost:3001 <пароль> shots` (браузер, компьютер + телефон).
- Локальный запуск без Turso: `npm start` (Node 22.13+), данные в `data/local.sqlite`, пароль `admin`.
- Регион: создайте базу Turso в регионе рядом с функциями Vercel (по умолчанию `iad1`, Вашингтон) — иначе каждый запрос медленнее.
- Лимиты бесплатного Turso проверьте в панели Turso; фото хранятся там же (одно фото ≈ 0,3–1,5 МБ).
